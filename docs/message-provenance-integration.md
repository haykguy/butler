# Message targeting: integration blocker and contract

**Status: unavailable; do not enable.** `butler.message_provenance.prepare_targeted_operation(action, platform, chat_id, message_id, arguments)` always raises `TargetingUnavailable`. It never sends or returns a request. This is an explicit fail-closed integration seam, not a provenance verifier. Both existing tool handlers already reject targeted actions; no changes to `imessage_tools.py` or live Mecha were made.

## Evidence inspected

The running Mecha host's Photon sidecar source is `~/.local/share/hermes-agent/plugins/platforms/photon/sidecar/index.mjs`. Its `/react` implementation resolves the space but first looks up `knownMessages` by **message ID alone**, falling back to `space.getMessage(messageId)` only on a miss (lines 1172–1179). Thus passing the active `spaceId` does not establish that a cached message belongs to it. `/unreact` uses a space/message-keyed local reaction handle, but is not independent proof of message provenance. The examined source advertises `/react` and `/unreact`; no `/x/reply`, `/x/edit` or `/x/unsend` route was found in that file. Mecha's plugin calls those `/x/` routes, but that is not evidence the running sidecar supports them. This was source inspection, not a real-channel operation or exhaustive verification of any other sidecar build.

Mecha records inbound IDs by wrapping adapter dispatch and outbound IDs by wrapping an internal async recorder; its current/latest message hints and chat normalization do not establish an authoritative profile-scoped operation boundary. Do not monkeypatch, share its cache, trust message text or latest-message hints, accept a chat supplied solely by the model, or infer edit/unsend ownership from an ID.

## Contract needed before replacing the seam

A supported gateway-owned interface must bind authenticated profile and active session to the exact opaque Photon space and message. At the same trusted boundary it must resolve the authoritative message *within that space* and perform the requested operation without substituting a global-ID cache entry. It must establish sender ownership for edit/unsend; unknown sender, unknown membership, missing/revoked session authorization, duplicate/ambiguous IDs, unsupported routes and stale state all fail closed. If lookup and mutation cannot be made atomic, the owner must define and enforce a race-safe version or immutable operation capability scoped to the exact profile, space, message, action and lifetime. A local boolean, caller-provided record, or separately checked ID is not such a capability. The backend remains responsible for Apple-side eligibility and returns actual outcomes; timeouts are unknown, not success.

For parent integration: keep the current disabled branches and capability reporting until the above interface and each actual route are implemented and tested. Once available, replace the rejecting seam with a narrow authenticated gateway adapter; pass active profile/session from trusted gateway context, not tool arguments, and route all reaction, reply, edit, unsend and threaded voice actions through it. Preserve exact identifiers without normalization and require explicit IDs. `/react` and `/unreact` cannot simply be called after a local precheck while their global cache behavior remains. No fallback to a normal send on any failure.

## Acceptance tests before enablement

Use an isolated profile and a controlled, explicitly authorized chat, without concurrently sharing Mecha's live consumer. Verify actual route discovery/version and end-to-end delivery separately for each action. Exercise same message ID in another space/profile, global-cache collision, forged/stale evidence, mismatched or revoked session, wrong sender for edit/unsend, expired/removed target, backend rejection, timeout and restart. Confirm no mutation or fallback on every denial and that capability output reflects only the tested backend. Unit tests in `tests/test_message_provenance.py` verify only the current deny-all seam; they are not end-to-end tests.
