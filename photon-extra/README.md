# Photon extras (not installed or enabled)

This is a project-owned sidecar module, not an HTTP server, a gateway plugin, or an authorization system. It implements only `/x/contact-card` and `/x/background`; every other path returns `null`. Nothing in this directory changes the running sidecar or enables the Butler tools. Do not expose this handler until the host supplies the security boundaries below.

## Evidence and semantics

Read-only inspection of a Photon sidecar install found `plugins/platforms/photon/sidecar/extras.mjs`, imported and called by that host's `index.mjs` after its shared-token check. That file implements both routes via `space.send(sdk.nativeContactCard())` and `space.send(sdk.background(pathOrClear))`; its installed `@spectrum-ts/imessage` builder describes both as fire-and-forget. The actual route dispatch therefore **does exist in that sidecar source**, contrary to any inference from searching only for route literals in `index.mjs`. This observation is not runtime discovery or proof of delivery. The account's own native name/photo is shared, not an arbitrary vCard. Background clear passes the SDK sentinel `clear`. `ok:true` here means `space.send` resolved, not recipient acceptance, delivery, or backend eligibility. Exceptions/timeouts may have occurred after a side effect: do not automatically retry.

## Integration contract

A Photon sidecar owner must explicitly import `createExtras` from `extras.mjs` and construct one instance using the same `resolveSpace` and `background` / `nativeContactCard` builders as its installed Spectrum provider. After its normal loopback token authentication and JSON parsing, call `await extras.handle(req.url, body, trustedContext)` and, if non-null, send its `status` and `data`. This is an integration design, **not a patch already applied**. A token alone does not establish active-session authorization. Do not wire an existing sidecar's extras in parallel on these paths or route unknown paths to it.

* `authorize({action, spaceId, context})` must return literal `true` only after verifying the live, non-revoked authenticated profile, active Photon session, exact opaque space, action-specific explicit user consent, and permission to share with that chat (including group implications). `context` must come from a trusted gateway boundary, never model-supplied JSON. Existing HTTP token and caller-provided `spaceId` are insufficient; if the host cannot provide this binding, do not install the handler. Deny by default.
* `withImageSnapshot(path, use, context)` must independently authorize image access and give `use` a private immutable snapshot path, call it **exactly once**, await it, and keep the snapshot alive until it finishes. It must enforce bounded regular supported image files and prevent symlink, hardlink, path escape, replacement and concurrent modification attacks; clean up afterward. A path supplied by the caller must never be passed straight to the SDK. The snapshot hook is deliberately not supplied here; the existing Python snapshot is not automatically callable from Node and its safety must be evaluated at the actual process boundary. Without this hook, set is unavailable; contact and clear do not need it.
* Host route and body size limits, request lifecycle, authentication, and control of authorized code are host responsibilities. Bind discovery to the same authenticated sidecar instance; do not infer implementation from source, a plugin file, an unknown `/healthz` response, or a stale runtime record.

## Availability

`extras.capabilities()` returns version 1 and booleans `contact_card`, `background_set`, `background_clear` based only on required injected functions. It does not check a particular session, SDK version correctness, host authentication, network, Apple capability, deployment, or backend acceptance. A host may expose this exact record through a new authenticated discovery route **only after** installing the handler and implementing the prerequisites; callers must explicitly probe that route at runtime, require matching version and literal `true`, and still enforce per-request authorization. No such endpoint exists as a result of this directory alone. The Python adapter currently has no capability handshake and must remain unwired until a trusted integration exists. An unknown route, stale discovery, unsupported SDK, timeout, or restart is unavailable/unknown, never success.

## Tests

Run `node --test photon-extra/extras.test.mjs` from the repository root. These use fixture SDK/space/auth implementations, not Photon or Apple, and do not establish actual delivery. Before any deployment, separately exercise an isolated account and explicitly authorized chat, real installed SDK, authentication and session revocation, cross-profile/space denial, group consent, image boundary attacks, failures and timeout/restart behavior. No live changes or real sends were made.
